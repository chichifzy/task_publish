## 1. 系统概览

这是一个轻量的任务发布系统。管理员和高级用户发布任务，普通用户接取并完成任务，完成后获得积分。

**一句话流程**：任务进入任务仓库 → 普通用户接取、抽取或被派发任务 → 填写完成情况并提交 → 审核人审核通过 → 普通用户获得积分。

**系统特点**
- **部署简单**：整个系统是一个可执行文件，前端页面已打包在里面。数据库是服务器本机的一个文件，不需要安装数据库服务。
- **规则由后端保证**：所有权限和业务规则都在服务器上检查。前端隐藏按钮只是为了好用，绕过前端直接调用接口也无法越权。

## 2. 角色与账号

### 2.1 三种角色

| 角色 | 怎么产生 | 数量 | 主要能力 |
|---|---|---|---|
| 管理员（Super Admin） | 部署时用命令行创建，不能注册 | 有且只有 1 个 | 管理公共仓库；有私有仓库；授予或撤销高级用户；审核公共任务 |
| 高级用户（Super User） | 管理员把普通用户提升为高级用户 | 不限 | 查看公共仓库；有私有仓库；向授权了自己的普通用户派发任务 |
| 普通用户（Member User） | 自己注册，注册后默认是普通用户 | 不限 | 接取、抽取任务；接收派发的任务；提交和放弃任务；授权高级用户 |

只有普通用户能接取任务，管理员和高级用户不能接取。

### 2.2 账号信息

每个账号有两个标识，注意区分：

| | 用户 ID | 用户名（昵称） |
|---|---|---|
| 用途 | 登录、搜索、授权、派发时用来指定某个人 | 展示用 |
| 规则 | 3–20 位英文字母或数字 | 1–32 个字符 |
| 能否重复 | **不能**，并且不区分大小写（`Abc` 和 `abc` 算同一个） | **可以**重复 |
| 能否修改 | 注册后不能改 | 目前没有修改入口 |

- 登录方式：用户 ID + 密码。密码长度为 8–72 个字符。
- 新用户的初始积分是 **20**。
- 页面上显示用户时，统一写成“用户名（用户 ID）”，例如“小明（xiaoming）”，避免同名用户混淆。

### 2.3 角色变化

```
            注册
             │
             ▼
        ┌─────────┐   管理员授予   ┌─────────┐
        │ 普通用户 │ ────────────> │ 高级用户 │
        │         │ <──────────── │         │
        └─────────┘   管理员撤销   └─────────┘

管理员：命令行创建，角色不能被修改
```

**高级用户被撤销后**会变回普通用户：
- 私有仓库被**冻结**：任务数据保留，只能查看，不能新建、编辑、删除或派发。
- 他**已经派发出去的任务仍然有效**，普通用户提交后，仍由他审核。
- 普通用户对他的**授权仍然保留**，但他已经不能派发任务。在普通用户的授权列表里，这条授权显示为“已被撤销高级用户身份，暂不能派发”。
- 他可以像普通用户一样接取任务。

**再次授予高级用户后**，私有仓库自动解冻，之前的数据和授权都恢复可用。

## 3. 功能与业务规则

### 3.1 任务

每个任务包含：

| 属性 | 说明 |
|---|---|
| 任务编号 | 系统自动生成。公共任务显示为 `G-数字`，私有任务显示为 `P-数字`。编号不会重复，删除后也不会被再次使用 |
| 任务描述 | 任务的具体内容，1–5000 个字符 |
| 积分奖励 | 完成任务能获得的积分，见下表 |
| 可见范围 | 仅公共任务有：“全体可见”或“仅管理员和高级用户可见” |
| 状态 | 仅公共任务有：“启用”或“禁用” |

任务**没有标题**。列表里用任务编号和积分区分任务，任务描述以小字显示在卡片里。

**积分奖励规则**

| 谁创建 | 允许的积分 |
|---|---|
| 管理员（公共仓库或自己的私有仓库） | 不小于 1 的整数（系统上限 10 亿，防止计算溢出） |
| 高级用户（自己的私有仓库） | 1–9 的整数 |
| 高级用户从公共仓库复制的任务 | 保留原积分，可以超过 9。只修改描述时可以保持原积分；**一旦修改积分，就必须改成 1–9** |

### 3.2 公共任务仓库

- 只有管理员能新建、编辑、删除公共任务。
- 各角色能看到哪些公共任务：

| | 启用 + 全体可见 | 启用 + 仅管理员和高级用户可见 | 禁用 |
|---|---|---|---|
| 管理员 | ✅ 看得到 | ✅ 看得到 | ✅ 看得到 |
| 高级用户 | ✅ 看得到 | ✅ 看得到 | ❌ |
| 普通用户 | ✅ 看得到，可以**主动接取** | ❌ 看不到，但可以**随机抽取** | ❌ 不能接取也不能抽取 |

- 管理员在列表里还能看到每个任务“有几人正在进行”。

### 3.3 私有任务仓库

- 管理员和每个高级用户各有一个私有仓库，只有拥有者本人能看到和使用。
- 拥有者可以在里面新建、编辑、删除任务。
- 可以把公共任务**复制**到私有仓库：
  - 复制出来的是**独立副本**，原任务修改或删除，副本都不受影响；修改副本也不影响原任务。
  - 高级用户只能复制自己看得到的任务，也就是启用的公共任务。管理员可以复制任意公共任务。
  - 副本卡片上会显示“复制自 G-x”。原任务被删除后，这个标记会消失，副本本身保留。
- **只有私有仓库里的任务能派发**，公共任务不能直接派发。

### 3.4 普通用户获得任务的三种方式

| 方式 | 来源 | 过程 | 审核人 |
|---|---|---|---|
| 主动接取 | 启用、全体可见的公共任务 | 在任务大厅点“接取” | 管理员 |
| 随机抽取 | 启用、仅管理员和高级用户可见的公共任务 | 抽取 → 只看到积分 → 决定接取或不接取 | 管理员 |
| 被派发 | 管理员或高级用户私有仓库中的任务 | 派发后直接生效，不需要普通用户确认 | 派发者本人 |

#### 随机抽取的具体规则

1. 点“抽取任务”，系统从可抽取的任务里随机选一个，**只显示积分值**，不显示任务描述和编号。
2. 用户可以选择：
   - **接取**：任务进入“我的任务”，这时才能看到任务描述。
   - **再抽一次**：换一个新的抽取结果。
   - **不接取**：清除这次的抽取结果。
3. 抽取次数不限，不接取也没有任何影响。
4. 用户**正在进行的任务会被跳过**，不会被抽到。
5. 每人同一时间只保留一个抽取结果。不处理的话，下次打开页面它还在。
6. 如果抽到之后、接取之前，管理员禁用了这个任务、把它改成全体可见，或者删除了它，接取时会提示“该任务已不可接取，请重新抽取”。

> 为什么普通用户看不到抽到的是哪个任务？抽取结果保存在服务器上，返回给浏览器的只有积分值。接取时，服务器按自己保存的记录创建任务，所以普通用户即使修改请求，也接取不了没抽到的隐藏任务。

### 3.5 派发与授权

普通用户自己决定谁能给自己派发任务：

**管理员派发**
- 普通用户在“设置”里有开关“接受管理员派发任务”，**默认关闭**。
- 只有开关打开时，管理员才能给他派发。

**高级用户派发**
- 普通用户在“设置”里搜索高级用户，可以输入用户 ID（需要完全一致，不区分大小写）或用户名的一部分。
- 搜到后点“授权”，**每次只能授权一个**，要授权多个就逐个操作。
- 被授权的高级用户才能给他派发任务。
- 普通用户随时可以取消授权。

**派发过程**
- 派发者在私有仓库的任务卡片上点“派发”，系统会列出所有允许他派发的普通用户，勾选一个或多个后提交，一次最多 100 人。
- 系统逐个处理每个人。某个人失败不影响其他人，页面会逐个显示结果。常见的失败原因有：
  - 用户不存在
  - 对方不是普通用户
  - 对方没有开启“接受管理员派发任务”
  - 对方没有授权你
  - 对方正在进行这个任务

**关闭开关或取消授权后**，之后不能再派发，**已经派发的任务仍然有效**。

### 3.6 不能重复接取

**同一个普通用户在完成某个任务之前，不能通过任何方式再次接取同一个任务**，包括主动接取、抽取和被派发。

- “完成之前”指任务处于“进行中”或“待审核”状态。
- 任务完成或放弃后，可以再次接取。
- 不同用户可以同时接取同一个任务，互不影响。
- 私有仓库里复制出来的副本是**不同的任务**。例如，用户正在做公共任务 G-1，仍然可以被派发它的副本 P-8。
- 这条规则由数据库的唯一约束保证，即使两个请求同时到达也不会重复接取。

### 3.7 任务快照

接取任务时，系统会**保存一份当时的任务描述和积分**。之后原任务被编辑、禁用或删除，都不影响已经接取的任务：用户看到的描述、能获得的积分、放弃时扣的积分，都以接取时的快照为准。

### 3.8 任务流程

```
                    接取 / 抽取后接取 / 被派发
                              │
                              ▼
                       ┌────────────┐
              ┌──────> │   进行中   │ ───────┐
              │        └────────────┘        │
              │              │ 填写完成情况   │
   审核不通过 │              │ 并提交        │ 放弃
  （附原因）  │              ▼               │（扣积分）
              │        ┌────────────┐        │
              └─────── │   待审核   │ ───────┤
                       └────────────┘        │
                              │ 审核通过      │
                              ▼              ▼
                       ┌────────────┐  ┌────────────┐
                       │  已完成    │  │   已放弃   │
                       │ +任务积分   │  │ -积分×50%  │
                       └────────────┘  └────────────┘
```

**提交**
- 只有“进行中”的任务能提交。完成情况需要 1–5000 个字符。

**审核**
- 由谁审核：派发的任务由**派发者**审核，主动接取和抽取的公共任务由**管理员**审核。
- **通过**：任务变为“已完成”，普通用户获得该任务的积分。
- **不通过**：必须填写原因，任务退回“进行中”。用户能看到退回原因，修改后可以再次提交。
- 有待审核的提交时，导航栏的“审核”旁边会显示数量。

**放弃**
- “进行中”和“待审核”的任务都能放弃。
- 扣除积分 = 任务积分 × 50%，**向下取整**。

  | 任务积分 | 放弃扣除 |
  |---|---|
  | 1 | 0 |
  | 7 | 3 |
  | 9 | 4 |
  | 200 | 100 |

- 只要当前积分 **≥ 0** 就能放弃，扣完后可以变成负数。例如 2 积分的用户放弃 9 积分的任务，积分变为 −2。
- **积分为负数时不能放弃任何任务**，只能把任务做完。
- 放弃前页面会弹窗提示要扣多少积分。

### 3.9 积分

| 事件 | 积分变化 |
|---|---|
| 注册 | 初始 20 |
| 任务审核通过 | + 任务积分（按接取时的快照） |
| 放弃任务 | − 任务积分 × 50%（向下取整） |

- 积分可以是负数。
- 每次积分变化都会写一条**积分流水**，记录变化值、原因和对应的任务，方便以后对账。目前页面上还没有查看流水的入口。
- 目前积分只用于展示：普通用户在页面顶部看自己的积分，管理员在用户管理里看所有人的积分。

### 3.10 删除任务的影响

| 删除对象 | 已接取的任务 | 其他影响 |
|---|---|---|
| 公共任务 | 不受影响（有快照），可以继续提交、审核 | 抽到这个任务但还没接取的抽取结果会被清除；私有仓库里的副本保留，但“复制自”标记消失 |
| 私有任务 | 不受影响，可以继续提交、审核 | 无 |

## 4. 页面说明

### 4.1 各角色看到的页面

| 页面 | 管理员 | 高级用户 | 普通用户 |
|---|---|---|---|
| 公共仓库 / 任务大厅 | ✅ 公共仓库 | ✅ 公共仓库 | ✅ 任务大厅 |
| 私有仓库 | ✅ | ✅ | 曾经是高级用户且私有仓库里有任务时显示“私有仓库（已冻结）” |
| 审核 | ✅ | ✅ | 有待自己审核的任务时显示（曾经是高级用户的情况） |
| 用户管理 | ✅ | | |
| 我的任务 | | | ✅ |
| 设置 | | | ✅ |

页面顶部显示当前用户的“用户名（用户 ID）· 角色”，普通用户还会显示积分。

### 4.2 任务卡片

所有任务都用统一的卡片显示：

```
┌──────────────────────────────────────────────────┐
│ G-12  9 积分  [全体可见] [启用] [2 人进行中]       │ ← 编号、积分、状态标签
│ 帮忙整理 3 月份的报销单据，按部门分类，汇总成一张   │ ← 任务描述（小字），
│ 表格，标注缺少发票的条目，并把汇总表发到财务群…    │   最多两行，超出用“…”
│                       [复制到私有仓库] [编辑] [删除]│ ← 操作按钮
└──────────────────────────────────────────────────┘
```

- 点击描述可以展开全文，再点一次收起。
- 标签颜色：蓝色表示可见范围或进行中，绿色表示启用或已完成，橙色表示仅管理员和高级用户可见或待审核，红色表示禁用，灰色是其他信息。

### 4.3 各页面功能

**公共仓库（管理员）**
- 顶部是新建表单：任务描述、积分、可见范围、状态。
- 每张卡片可以复制到私有仓库、编辑、删除。点“编辑”后，顶部表单变成编辑模式。

**公共仓库（高级用户）**
- 查看启用的任务，可以复制到私有仓库。

**任务大厅（普通用户）**
- 顶部是“随机抽取”区域。
- 下方是可以主动接取的任务。正在进行的任务，按钮显示为灰色的“进行中”。

**私有仓库（管理员、高级用户）**
- 新建、编辑、删除私有任务。表单下方会提示积分规则。
- 点“派发”展开派发面板：列出允许派发的普通用户，可以按用户 ID 或用户名筛选，勾选后派发，并逐个显示结果。
- 被冻结时只显示任务列表和冻结说明。

**审核（管理员、高级用户）**
- 列出待自己审核的提交，显示任务描述、提交人、来源和完成情况。
- 填写审核意见（不通过时必填），然后点“通过”或“不通过”。

**用户管理（管理员）**
- 列出所有普通用户和高级用户，高级用户排在前面，最多显示 200 条。可以按用户 ID 或用户名搜索。
- 可以把普通用户设为高级用户，或撤销高级用户。撤销前会弹窗说明撤销的影响。

**我的任务（普通用户）**
- 按“未完成 / 已完成 / 已放弃 / 全部”筛选。
- 进行中的任务可以填写完成情况并提交。被退回的任务会显示退回原因。
- 未完成的任务有“放弃（−扣除分数）”按钮。积分为负数时这个按钮不能点。

**设置（普通用户）**
- “接受管理员派发任务”开关。
- 搜索并授权高级用户。
- 已授权的高级用户列表，显示每个人当前能否派发，可以取消授权。

## 5. 技术架构

### 5.1 技术选型

| 层 | 技术 | 选择理由 |
|---|---|---|
| 后端 | Go，只用标准库 `net/http` | 编译成一个可执行文件，服务器上不需要安装运行环境，内存占用小 |
| 数据库 | SQLite，驱动是 `modernc.org/sqlite`（纯 Go 实现，不需要 CGO） | 整个数据库就是一个文件，不需要安装和维护数据库服务，备份时复制文件即可 |
| 前端 | React 19 + React Router + TypeScript，用 Vite 构建 | 开发效率高；构建后只有几个静态文件 |
| 密码 | bcrypt | 业界标准的密码哈希算法 |

除了 SQLite 驱动，后端只依赖两个官方扩展库：`golang.org/x/crypto`（bcrypt）和 `golang.org/x/term`（命令行读取密码时不回显）。

### 5.2 运行结构

```
                浏览器
                  │  HTTP
                  ▼
┌──────────────────────────────────────────┐
│        task_publish（一个可执行文件）      │
│                                          │
│  /api/*  →  JSON 接口（认证、业务逻辑）    │
│  其他路径 →  前端页面（打包在可执行文件里） │
└──────────────────────────────────────────┘
                  │
                  ▼
            data.db（SQLite 文件）
```

- 前端构建产物通过 Go 的 `go:embed` 打包进可执行文件。
- 前端页面和接口同域，浏览器自动携带登录 Cookie，不存在跨域问题。
- 前端用 React Router 管理页面路由。直接访问 `/mine` 这类地址时，后端返回首页，再由前端渲染对应页面。
- 前端静态资源的文件名带内容哈希，所以设置为长期缓存。

### 5.3 数据库连接设置

| 设置 | 作用 |
|---|---|
| WAL 模式 | 读和写可以同时进行 |
| 最多 1 个连接 | SQLite 同一时刻只允许一个写入者。所有请求排队使用这个连接，避免“数据库被锁”的错误。对这个规模的系统速度足够 |
| `busy_timeout=5000` | 遇到锁时最多等 5 秒 |
| 开启外键约束 | 保证数据之间的引用关系正确 |
| 事务一开始就加写锁（`_txlock=immediate`） | 避免“先读后写”的事务中途加锁失败 |

> 开发注意：数据库只有一个连接，所以在事务里只能用事务对象 `tx` 执行语句。如果在事务里再用 `db` 执行，会一直等待这个连接，造成死锁。

### 5.4 关键业务的并发安全

| 场景 | 怎么保证正确 |
|---|---|
| 同一用户重复接取 | 数据库部分唯一索引：同一用户和同一任务，只能有一条“进行中/待审核”的记录 |
| 用户 ID 重复注册 | 用户 ID 列有唯一约束，并且不区分大小写 |
| 多于一个管理员 | 部分唯一索引：`role = 'admin'` 的行最多只有一条 |
| 积分计算 | 修改积分和写积分流水在同一个事务里完成 |
| 审核、放弃 | 在事务中先检查状态再修改，两个请求不会同时成功 |

### 5.5 数据库迁移

- 表结构写在 `internal/db/migrations.go` 的列表里，程序启动时自动执行还没执行过的迁移。
- 已执行到第几条，记录在 SQLite 的 `user_version` 里。
- **要修改表结构时，在列表末尾追加一条新迁移，不要改已经发布的旧迁移。**

## 6. 数据库设计

### 6.1 表关系

```
users ─┬─< sessions          一个用户可以有多个登录会话
       ├─< tasks             owner_id：为空是公共任务，否则是该用户的私有任务
       ├─< authorizations    普通用户 → 高级用户 的授权
       ├── draws             每人最多一条当前抽取结果
       ├─< assignments       接取记录（user_id 是接取人，reviewer_id 是审核人）
       └─< points_log        积分流水

tasks ──< assignments        只记编号，任务删除后接取记录保留
tasks ──< tasks              copied_from：副本 → 来源公共任务
```

### 6.2 表结构

**users：用户**

| 字段 | 说明 |
|---|---|
| id | 内部编号，不对外展示 |
| uid | 用户 ID，唯一，不区分大小写 |
| nickname | 用户名 |
| password_hash | bcrypt 哈希后的密码 |
| role | `admin` / `super` / `member` |
| accept_admin_dispatch | 是否接受管理员派发，默认 0（关闭） |
| points | 积分，默认 20，可以是负数 |
| created_at | 注册时间 |

**sessions：登录会话**

| 字段 | 说明 |
|---|---|
| token_hash | 会话凭证的 SHA-256 哈希（不保存原文） |
| user_id | 所属用户 |
| expires_at | 过期时间（7 天） |

**tasks：任务（公共和私有共用一张表）**

| 字段 | 说明 |
|---|---|
| id | 任务编号，自增且不复用 |
| owner_id | 为空表示公共任务；否则是私有仓库拥有者 |
| description | 任务描述 |
| points | 积分奖励，≥ 1 |
| visibility | `all` / `privileged`，仅公共任务使用 |
| enabled | 1 启用 / 0 禁用，仅公共任务使用 |
| copied_from | 复制来源的公共任务编号，来源删除后置空 |
| created_at / updated_at | 创建和修改时间 |

“私有仓库冻结”没有单独的字段：拥有者当前不是管理员或高级用户，仓库就视为冻结。

**authorizations：派发授权**

| 字段 | 说明 |
|---|---|
| member_id | 授权人（普通用户） |
| super_id | 被授权的高级用户 |
| created_at | 授权时间 |

主键是 `(member_id, super_id)`，同一对授权只有一条。

**draws：当前抽取结果**

| 字段 | 说明 |
|---|---|
| user_id | 主键，每人一条 |
| task_id | 抽到的任务，任务删除时这条记录一并删除 |

**assignments：接取记录**

| 字段 | 说明 |
|---|---|
| id | 记录编号 |
| task_id | 来源任务编号（不设外键，任务删除后仍保留，用来显示编号） |
| task_public | 来源是否是公共任务，用来显示 G- 或 P- |
| user_id | 接取人 |
| reviewer_id | 审核人：派发的任务是派发者，公共任务是管理员 |
| source | `claim` 主动接取 / `draw` 随机抽取 / `dispatch` 被派发 |
| description / points | 接取时的任务快照 |
| status | `in_progress` 进行中 / `submitted` 待审核 / `completed` 已完成 / `abandoned` 已放弃 |
| submission | 完成情况 |
| review_note | 审核意见（不通过的原因） |
| created_at / updated_at | 接取和最近更新时间 |

唯一索引 `(user_id, task_id) WHERE status IN ('in_progress', 'submitted')` 实现“完成前不能重复接取”。

**points_log：积分流水**

| 字段 | 说明 |
|---|---|
| user_id | 用户 |
| delta | 变化值（正数为加，负数为扣） |
| reason | `complete` 完成 / `abandon` 放弃 |
| assignment_id | 对应的接取记录 |
| created_at | 时间 |

## 7. 接口列表

所有接口都以 `/api` 开头，请求和响应都是 JSON。出错时返回 `{"error": "中文错误信息"}`。

### 7.1 常见状态码

| 状态码 | 含义 |
|---|---|
| 200 / 201 / 204 | 成功（201 表示新建成功，204 表示成功但没有返回内容） |
| 400 | 参数不合法 |
| 401 | 没有登录或登录已过期 |
| 403 | 角色没有权限 |
| 404 | 对象不存在，或你无权看到它 |
| 409 | 状态冲突，例如重复接取、任务状态不允许当前操作、积分为负时放弃 |
| 415 | 请求的 Content-Type 不是 `application/json` |

### 7.2 认证与个人

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | /auth/register | 公开 | 注册普通用户：`uid`、`nickname`、`password` |
| POST | /auth/login | 公开 | 登录：`uid`、`password` |
| POST | /auth/logout | 公开 | 退出登录 |
| GET | /me | 登录 | 当前用户信息、积分、待审核数量、私有仓库是否有任务 |
| PUT | /me/settings | 普通用户 | 设置 `acceptAdminDispatch` |

### 7.3 公共仓库

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /public/tasks | 登录 | 按角色返回看得到的任务 |

### 7.4 随机抽取

| 方法 | 路径 | 权限 | 说明 |

### 7.5 私有仓库与派发

| 方法 | 路径 | 权限 | 说明 |

| DELETE | /private/tasks/{id} | 管理员、高级用户 | 删除 |
| POST | /private/tasks/{id}/dispatch | 管理员、高级用户 | 派发：`uids` 数组，返回每个人的结果 |
| GET | /dispatch-targets | 管理员、高级用户 | 允许自己派发的普通用户列表 |

### 7.6 接取记录与审核

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|

| POST | /assignments/{id}/submit | 接取人本人 | 提交：`submission` |
| POST | /assignments/{id}/abandon | 接取人本人 | 放弃，返回扣除的积分和剩余积分 |
| GET | /reviews | 登录 | 待我审核的提交 |
| POST | /assignments/{id}/review | 审核人本人 | 审核：`approve`（true/false）、`note` |

### 7.7 授权

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|

| DELETE | /authorizations/{uid} | 普通用户 | 取消授权 |

### 7.8 用户管理

## 8. 安全设计

| 方面 | 做法 |
|---|---|
| 密码 | 用 bcrypt 哈希保存，不保存明文 |
| 登录凭证 | 32 字节随机值，放在 Cookie 里；数据库只保存它的 SHA-256 哈希，数据库泄露也无法冒充登录 |
| Cookie | `HttpOnly`（网页脚本读不到）、`SameSite=Lax`；HTTPS 部署时加 `-secure-cookie` 参数开启 `Secure` |
| 会话 | 有效期 7 天；退出时删除；每次登录时顺带清理过期会话 |
| 防跨站请求伪造（CSRF） | 所有写操作都要求 `Content-Type: application/json`，其他网站的表单无法发出这种请求；再加上 SameSite Cookie |
| 防用户 ID 探测 | 用户 ID 不存在时也做一次密码比对，响应时间和“密码错误”时相同，无法通过时间差判断某个 ID 是否存在 |
| 权限 | 每个接口在后端检查角色；角色每次请求都从数据库读取，撤销高级用户后**立即生效** |
| 数据隔离 | 私有任务、接取记录、审核都按“拥有者 / 接取人 / 审核人”过滤。访问别人的数据时统一返回 404，不暴露数据是否存在 |
| 输入校验 | 所有字段都校验长度和格式；JSON 里出现未知字段直接拒绝（例如注册时想加 `"role":"admin"` 会被拒绝）；请求体最大 1MB |
| SQL 注入 | 全部使用参数化查询；搜索时转义 `%` 和 `_` |
| 错误信息 | 服务器内部错误只返回“服务器内部错误”，详细信息只写进日志 |
| 管理员密码 | 命令行创建时从终端读取，不回显，也不作为命令行参数，所以不会留在 shell 历史里 |

## 9. 开发、测试与部署

### 9.1 环境要求

- 开发机：Go 1.22 及以上、Node.js、pnpm
- 服务器：**什么都不用装**，只需要编译好的可执行文件

### 9.2 本地开发

开两个终端：

```bash
make dev-api   # 终端 1：启动 Go 服务，端口 8080，数据库 data.db
make dev-web   # 终端 2：启动 Vite，端口 5173，/api 请求转发到 8080
```

浏览器访问 http://localhost:5173 。修改前端代码后页面自动刷新，修改 Go 代码后需要重启终端 1。

首次使用先创建管理员：

```bash
go run . -db data.db create-admin admin 管理员
# 按提示输入两次密码
```

### 9.3 测试

```bash
go build -o bin/task_publish . && scripts/smoke.sh
```

`scripts/smoke.sh` 会启动一个使用临时数据库的服务，覆盖本文第 3 章的主要规则：账号、可见性、接取、抽取、快照、提交审核、放弃扣分、授权派发、撤销高级用户、负积分等。最后输出“全部通过”或失败的项目。

### 9.4 构建

```bash
make build         # 本机版本，输出 bin/task_publish
make build-linux   # Linux x86-64 版本，输出 bin/task_publish-linux-amd64
```

构建时会先编译前端，再把前端打包进 Go 可执行文件，大小约 10MB。

### 9.5 部署

1. 把可执行文件拷贝到服务器。
2. 创建管理员（只需一次）：
   ```bash
   ./task_publish -db /var/lib/task_publish/data.db create-admin <用户ID> <用户名>
   ```
3. 启动服务：
   ```bash
   ./task_publish -addr :8080 -db /var/lib/task_publish/data.db
   ```

**命令行参数**

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-addr` | `:8080` | 监听地址 |
| `-db` | `data.db` | 数据库文件路径，不存在时自动创建 |
| `-secure-cookie` | 关闭 | 通过 HTTPS 访问时开启 |

**建议**
- 前面放一个 Caddy 或 Nginx 提供 HTTPS，并加上 `-secure-cookie`。
- 用 systemd 管理进程。程序收到停止信号后，会等正在处理的请求完成（最多 10 秒）再退出。
- **备份**：运行中用 `sqlite3 data.db ".backup backup.db"`；或者停服后直接复制 `data.db`。运行中不要只复制 `data.db`，因为 WAL 模式下还有 `data.db-wal` 文件。
- 日志输出到标准输出，每个接口请求记录方法、路径、状态码和耗时。
